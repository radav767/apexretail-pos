# Phase 11 read-only reconciliation export contract — 26 November 2026

`GET /api/reports/reconciliation/{company_id}/export.zip` produces a versioned CSV/JSON snapshot. It is an export for review, **not a live accounting integration**, posting, provider or fiscal confirmation. No journal entries, mappings, vendor credentials, delivery or ledger mutations. Production and Super Admin remain NO-GO; posting capabilities remain default-disabled/test-only.

Current tenant identity/epoch, revenue and credit-settlement permissions and authorized branch/shift scope are required. Employee reads default to their own branch. Historical reads survive subscription expiry. A second current-context check before returning bytes rejects revocation during generation. Previously downloaded files cannot be revoked; clients must discard delayed downloads after identity changes.

Aware UTC half-open bounds, positive interval at most 366 days. Sale/refund receipt creation and collection received-at are their own event dates. One SQL statement reads the entire financial snapshot. Receipt rows never join tender/item/collection detail; this avoids multiplication. Maximum 10,000 events **and** 10,000 receipts and 16 MiB uncompressed bundle content; oversized exports fail with no partial download. Fixed 200-row numbered CSV pages are internal to the same bundle, including a header-only page for empty results. New requests create new snapshots; there is no retained server snapshot ID or cross-request pagination guarantee.

`snapshot.json` preserves stored signed decimal strings and raw historical text, with original event kinds, receipt rows, payment/debt totals and cash original-unit totals. `events-*.csv` and `receipts-*.csv` are typed presentation copies. `receipt-totals.csv` groups signed billed revenue and tax separately by sale/refund and base currency. `flow-totals.csv` groups original payments, credit origination, collections, paid refunds and debt reductions separately by base currency, event kind, method and original currency. Revenue, collection, debt and drawer measures must never be added together. Debt is a dated delta, not an as-of outstanding balance or opening debt ledger. Full debt/current receivable reconciliation remains a separate report.

Cash tender, change, net original units, frozen-rate drawer valuation and allocation/tender-change FX residuals remain separate. Missing legacy evidence is null plus explicit unknown counts, never fabricated zero. Do not sum different currencies. Historical discounts/subtotals are the stored values; no claim to reconstruct absent legacy discounts. Internal costs/profits and current customer/catalog details are excluded. Rates, receipt identities and amounts never use current settings or catalogues.

CSV text is apostrophe-prefixed for formula-leading operators after whitespace/BOM, and leading tab/CR/LF/BOM. Only declared finite numeric fields bypass text sanitisation, retaining negative refund numbers. Raw JSON must be treated as untrusted data if imported into spreadsheets. Manifest SHA-256 and lengths bind every payload file; archive filenames are fixed, versioned and contain no uploaded path. Deterministic package generation preserves the supplied snapshot's exact bytes; generation time and newly read rows can differ on new requests. Downloads are no-store and nosniff. No stored historical document, receipt, output or print job is regenerated or altered.

Acceptance must include persisted synthetic payment/collection/refund ledgers, exact replay, both FX residuals/change, date boundaries, limits/pages, tenant/branch/role/revocation, hostile text, download identity changes and independent reader/writer concurrency. Software acceptance never establishes physical printer, installed-device, vendor sandbox or assistive-technology certification. Preserve every existing revocation/lease/queue/command and immutable-evidence guard in rollback or forward recovery.
