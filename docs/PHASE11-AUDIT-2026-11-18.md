Evidence levels used below:

- **Verified subset:** specifically rerun in this audit.
- **Existing:** implementation inspected, with historical tests identified; not freshly certified end to end.
- **Partial:** some requested behavior exists, with identified gaps.
- **Missing:** no corresponding implementation found in inspected application modules; excludes unconnected external systems.
- **Unverified:** deployment, hardware, provider or policy proof remains unavailable.

## 4. Security and operational priorities

1. **Release/source drift — critical release risk.** Reconcile exact deployed fixes and runtime dependencies before any runtime work or deployment. Old checkout builds could regress authentication, product, printer, commercial and fiscal modules.
2. **Cross-account Backoffice entry — high.** The POS URL opener does not bind account context; persistent independent Backoffice tokens can expose a previous user's session. Confirm with isolated two-account browser tests, then implement handoff/invalidation.
3. **Business session revocation — high.** User JWT authentication lacks the revocable remembered-session lifecycle requested. Reset/logout/revocation must reject already issued sessions server-side. Review owner shortcuts and branch restrictions in all permission helpers; do not assume every authenticated user has owner authority.
4. **Offline trust — high.** Cryptographic authenticity is implemented, trustworthy offline time/revocation is not demonstrated. Product policy must specify bounded disconnected operation and fail-closed recovery without deleting queued business records.
5. **Secret configuration — high conditional risk.** Config requires `jwt_secret`, but security module retains a known fallback when the supplied setting is empty. Add fail-closed nonempty/strength validation; this audit did not inspect secret values or establish that production uses the fallback. Do not rotate credentials without approval.
6. **Super Admin/recovery — deployment blocker.** Existing technical closure records incomplete backend validation and real two-role restore, protected migration/runtime identity and rollback gates. Installed API unit does not declare a non-root User; historical evidence reports UID 0. Non-root migration requires tested media/access/worker compatibility and separately approved operations.
7. **Android signer — release constraint.** Preserve current package/certificate, including the established signing configuration. Do not silently switch signers or use acceptance package as an upgrade. Compare signer fingerprints/version and test in-place upgrades before approval.
8. **Sensitive document/provider data.** Enforce tenant/branch authorization on files, lookup tokens and delivery jobs; minimize personal information, protect voucher codes and provider credentials, redact audit logs, and prevent uploaded-logo/template script injection and remote-fetch abuse.
9. **Finance/inventory concurrency.** All conversion/receiving/return/dispatch paths require transaction boundaries, unique idempotency keys and reconciled immutable movements. Stock-take stale-count rejection exists and must be preserved.
