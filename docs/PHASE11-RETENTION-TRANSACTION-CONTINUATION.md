# Retention and transaction continuation invariants

21 November 2026 UTC; isolated development only. Production and Super Admin NO-GO. Complements existing document, procurement/count, quotation and split-tender contracts.

Retention never means deletion or rewriting of an immutable logo, template, document, output, consent, capture or command proof. Archival is a separate versioned projection with append-only original request evidence. It blocks new logo selection, while frozen templates and historical output remain reproducible. Reactivation is a new licensed configuration change; archive/recovery remains available after expiry with current owner/tenant/branch/security authority. Archived assets still count toward the hard64 archive bound. Identical normalized PNG in the same tenant/branch reuses the original identity, never burns another slot or silently reactivates archived content. No legal retention period, scheduled purge, right-to-erasure implementation or key rotation is inferred from this work.

New PDFs may use the packaged, licensed and SHA256-pinned DejaVuSans renderer profile. Existing output lookup remains document/format based and returns original stored bytes/engine; upgrades do not regenerate historical artifacts. NFC is applied for new PDF display only, never to stored transaction/command payloads or amounts. Glyph coverage is checked, RTL/bidi control and residual combining/shaping requirements fail explicitly; this is bounded Latin/Greek/Cyrillic/currency coverage, not universal Unicode or tagged accessible PDF certification. New HTML has explicit English interface language, one main heading, table captions/column scopes and escaped source text. UI controls need accessible names, selected-state and status announcements, keyboard focus and synthetic browser checks. Physical device/screen-reader/print acceptance stays separate.

Before extending transaction behavior:

* Quotation revisions create linked new drafts; original frozen items, commercial terms, validity, approvals and prior documents remain unchanged. A revision lineage can own at most one conversion. Creating a draft does not itself post stock/payment or fabricate acceptance. Immutable request/input/actor/register proof identifies the new draft; explicit acceptance is needed for its new terms. Shared lineage locking must precede order/checkout locks and conversion/revision races must serialize. Never silently revise a converted quotation or transfer acceptance to a child.
* Discounts, custom units and currency support require parity with checkout. Round exactly once in the currency minor unit using Decimal/ROUND_HALF_UP; discount is capped by eligible gross before tax, item/sale discounts allocate deterministic residual minor units and cannot create negative bases/tax. Freeze entered/base quantities, unit conversion, currency/config/rate and original item/tax/discount/cost snapshots. A conversion uses the accepted terms or conflicts atomically; it must not reprice after stock changes or bypass discount/override permissions. Existing two-decimal/base-unit/zero-discount gates stay closed for any path without complete parity proof.
* Split accounting uses one sale and stock effect, original stable leg IDs and exact applied base/original currency amounts. Weighted minor-unit allocation uses largest fractional remainder then stable leg UUID, never input order or float arithmetic. Base allocations sum exactly to tax-inclusive sale total. Cash tender/change belongs only to its original currency; credit applied amount is unpaid receivable, never cash. Provider-backed/offline legs remain disabled without existing signed action/provider confirmation contracts.
* Cumulative refund allocation consumes only original unrefunded leg budgets; unpaid credit reduces debt first, then paid allocations in persisted deterministic order. Final reversal consumes exact residual cents. Original paid amounts/rates never change, collections are dated flows rather than revenue, and a paid-credit excess cannot silently become cash payout or negative debt. Quote/rounding and refund preview/planning code alone is not posted split-tender acceptance. API/UI/report/receipt/stock/return/concurrency parity is required before enablement.

Every compatible forward recovery retains epochs, opaque/browser sessions, leases, original offline queues, stock cutoffs, cancellation fences and all immutable accounting/document/consent evidence. No real delivery/payment/fiscal/provider action or APK is authorized.
