# Private document assets and output contract

21 November 2026 UTC. Development only; production and Super Admin NO-GO.

Uploads are tenant/optional-branch owner/admin configuration under current license. Accept only declared PNG/JPEG/WebP that fully decode as a single frame. Bound envelope, bytes, dimensions, pixels and normalized PNG output; strip metadata and re-encode a fresh raster, never retain uploaded HTML/SVG/URLs/file paths or original bytes/name. Immutable DB assets avoid public filesystem paths. Current tenant/branch/settings permissions govern reads; immutable templates freeze media digest/content for historical reproduction. One bounded logo per layout, fixed alignment/width, safe escaped contact/text, source-only items/tax/totals blocks; no script, CSS or expression language. Old template command fingerprints and v1 document HTML remain unchanged.

Use an additive pinned document dependency profile in an isolated venv, never an inherited production profile. Pixel limits are checked before decoding, warnings become errors, full verify/load precedes re-encoding. References: [Pillow image API](https://pillow.readthedocs.io/en/stable/reference/Image.html), [ReportLab canvas](https://docs.reportlab.com/reportlab/userguide/ch2_graphics/), [qrcode](https://pypi.org/project/qrcode/). No artwork is generated or presented as official branding.

PDF outputs are separately identified immutable artifacts from the stored source/template snapshot, not arbitrary HTML rendering. Use bounded local text/raster layout and embedded known font; no URL/file fetches or executable PDF annotations. Page, input and output bounds must fail before commit. Store engine version, source/content digests and bytes so repeated downloads do not change historical content after engine updates. Payment/stock/fiscal/printing identities are untouched. Device/paper/Unicode/physical printer acceptance remains distinct from parser/browser evidence.

QR initially supports only authenticated document lookup: a fixed non-URL payload naming company/document and content digest, no bearer/reset/handoff/PIN credentials or customer/payment data. Resolution is an authenticated API read with current source permissions. No public token or arbitrary destination. Payment and fiscal QR are unavailable without approved provider/authority evidence; do not manufacture URL/status/success. Generate bounded raster, retain original output identity and test software decode; physical scan acceptance remains pending.

Delivery is consent-aware and sink-only. Enqueue identified immutable original document/output with an explicit purpose/recipient and current consent grant, all tenant/branch/source-role checks. Consent revocation and current permissions/epochs are rechecked at processing; expired accounts may read/retain/cancel evidence but new sends need current license. Never use a provider transport in this implementation. A sink acknowledgement is named captured, never delivered/provider success. Preserve original command UUID and attempt identity on loss/retry; serialize queue/consent changes and atomically store capture/attempt/status. Test encryption of recipient/content at rest with an explicit test-only key; no real email addresses, credentials or outbound calls. Production mode must fail closed for sink processing. Unknown provider outcomes are not simulated as success. Forward recovery retains every revocation, queue, cutoff, cancellation fence, immutable template/source/artifact and command proof.
