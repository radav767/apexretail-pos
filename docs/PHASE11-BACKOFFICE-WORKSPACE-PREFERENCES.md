# Bounded Backoffice workspace preferences — 26 November 2026

Explicit `backoffice-workspace-preferences-v3` extends scoped presentation with `backoffice_workspace_view` (tiles/list) and `backoffice_text_size` (standard/large). Both are optional per-key overrides. Defaults tiles/standard; company → branch → assignment-bound device inheritance remains unchanged. Backoffice Sales & Reports hub, settings section/group navigation and preference-editor preview consume these fields in the accepted bounded increments. The hub consumes company scope because Backoffice has no global selected branch/device context. Branch/device effects are visible in scoped editor previews, not falsely applied as a global Backoffice context. Other screens and POS checkout remain unchanged.

V1 and v2 request classes, model dumps, UUID namespace and original immutable acknowledgements must stay byte/shape compatible. Old writers own only their original fields and preserve newer fields they cannot represent; explicit v3 clears only fields it owns. Metadata retains v2 contract marker for existing clients and advertises a separate workspace-preferences capability. A new editor uses v3 only when advertised, otherwise retains v2/v1 writes and disables unsupported workspace controls. Exact lost-response recovery reuses the original body/UUID/version, never regenerates a replacement on uncertainty. Current identity, role, version, license and assignment rules remain authoritative.

Large means bounded minimum20px /1.25rem readable hub/settings-navigation/editor text, at least44px controls, visible focus and wrapping at narrow width. It never disables browser zoom, OS forced colours or reduced motion. List is a single-column hub layout; tiles retain existing responsive layout. It never hides recovery destinations or changes permissions, report/financial values, terminal operation, output/document bytes or posting flags. Empty scope clears inherit without altering older acknowledgements or unrelated settings. Read failures/defaults never clear queues or sign out users.

This is partial workspace presentation acceptance, not full workspace theming, ten-section taxonomy, native assistive-technology or cross-browser certification. No POS administration hierarchy. Original security/revocation/lease/queue/proof/immutable evidence rules remain; production/Super Admin NO-GO and unsupported capabilities remain gated.

Recovery limitation: preference saves retain original bodies for retry in the same mounted editor; the existing preference mechanism does not durably discover uncertain saves after a reload/identity change. Read back/version conflicts require authorized review. This is not a new cross-browser pending-request system. Rollback may hide new UI while retaining the v3 parser/field-ownership rules and original command records; do not roll back revocation/security enforcement or deploy a legacy writer that erases newer overrides. Historical acknowledgements/documents are never rewritten.
